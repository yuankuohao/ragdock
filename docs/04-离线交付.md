# 离线交付

客户在隔离网时，镜像、配置、文档全部靠移动介质带进去。

## 有网机器

```bash
make up                 # 先确认整套能跑通
make offline-save       # 导出到 offline/ragdoc-images-YYYYMMDD.tar.gz
```

会生成三个文件：

```
offline/ragdoc-images-YYYYMMDD.tar.gz   镜像归档（约 8–12 GB）
offline/images-YYYYMMDD.txt              镜像清单，便于核对
offline/MANIFEST.txt                     版本与时间
```

带上移动硬盘时，除了 `offline/`，还要带：

- `upstream/`（RAGFlow 官方 compose 与 .env，否则目标机拉不到）
- `.env`（**含密钥，交付前确认客户是否要自己填**）
- 整个仓库（脚本与文档）

## 目标机器

```bash
tar -xzf ragdoc-bundle.tar.gz && cd ragdoc
./scripts/offline-load.sh offline/ragdoc-images-YYYYMMDD.tar.gz
make up
```

`make up` 里的 `make fetch` 会因无网失败，所以 **upstream/ 必须随包带过去**，脚本检测到文件存在会直接跳过下载。

## 用本地模型时的额外步骤

`profiles/ollama.env` 走宿主机 Ollama，镜像里不含模型权重。离线机器上：

```bash
# 在有网机器拉好模型，导出整个 ollama 数据目录（默认 ~/.ollama/models）
tar -czf ollama-models.tar.gz -C ~/.ollama models

# 目标机器还原后启动 ollama 容器，再切预设
make model PROFILE=ollama
```

如果客户完全不允许任何外部模型，这是唯一选择；7B 模型在 16 GB 内存的机器上约 5–8 秒/答，够用但不快。
