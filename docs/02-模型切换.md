# 模型切换

## 原理

RAGFlow 只认**一个** OpenAI 兼容地址。我们把 LiteLLM 放在它前面，由网关决定 `chat-default` 背后到底是哪家模型：

```
RAGFlow ──base_url──▶ http://<host>:4000/v1 ──▶ chat-default  ──▶ DeepSeek / Qwen / Kimi / GLM / Ollama
                                            └─▶ embed-default ──▶ 对应向量模型
```

所以换模型**不需要**动 RAGFlow 的知识库、助手、会话，也不用重新解析文档。

## 三种切法

**1. 用预设（最常用）**

```bash
make model PROFILE=qwen      # deepseek | qwen | kimi | glm | openai | ollama
```

预设文件在 `profiles/*.env`，包含聊天与向量两组。可自行复制一份改成客户的模型。

**2. 只换聊天模型，不动向量**

```bash
make model-chat \
  LLM_MODEL=qwen-max \
  LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1 \
  LLM_API_KEY=sk-xxx
```

**3. 在 RAGFlow 页面里直选**

网关把 `chat-default` 和具体模型名都注册了。RAGFlow 的模型下拉里会同时出现 `chat-default`、`deepseek-chat`、`qwen-plus` 等，改助手绑定的模型即可，**连网关都不用重启**。

## 两个必须知道的限制

1. **换向量模型要重建知识库。** RAGFlow 在 `chunk_count > 0` 时不允许改 `embedding_model`，因为旧向量与新向量不在同一空间。正确做法：新建知识库 → 重新解析 → 切换助手绑定。所以向量模型在建库前定好，之后尽量别动。
2. **不是每家都有向量接口。** DeepSeek、Kimi 只有聊天；GLM 有 `embedding-3`；通义有 `text-embedding-v4`；Ollama 可跑 `bge-m3`。预设里已经按这个规则配好，混搭时留意图里两行的 base_url 可以不同。

## 模型 ID 的写法

在 RAGFlow 里，模型标识是 `<模型名>@<供应商名>`。供应商名是你在「模型供应商」里取的别名，比如 `gateway`，那么：

```
chat-default@gateway
embed-default@gateway
```

聊天助手里选哪一个都可以：选 `chat-default` 以后换模型只改网关；选具体模型名则切换更直观但每次要改助手。

## 排错

```bash
make smoke                                  # 分别验证聊天与向量
docker compose logs -f gateway              # 看 LiteLLM 的上游报错
curl -s localhost:4000/v1/models \
  -H "Authorization: Bearer $LITELLM_MASTER_KEY" | head -40
```

常见错误：`api_base` 少了 `/v1`；key 填成了模型的而不是网关的；模型名在该厂商不存在（返回 404 model_not_found）。
