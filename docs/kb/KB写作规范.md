# KB 写作规范

> 状态：现行。何时翻它：新增、合并或归档 KB 专题前。

## 一篇一个主题

文件名 `NNN_主题.md`，标题与索引条目一致。排查经验、操作步骤、配置说明不混写；跨主题内容用链接引用，不复制正文。

## 索引先于正文

每篇在 `docs/kb/README.md` 登记一行，格式：

```
- [NNN 主题](NNN_主题.md) — 何时翻它：<触发场景>。
```

正文首行标题下写明状态与触发场景：

```
> 状态：现行。何时翻它：<触发场景>。
```

## 只写可复用的事实

- 写结论和判据，不写过程流水账。
- 命令必须能直接执行；路径用仓库相对路径。
- 版本号、镜像 tag、端口写死成当前实测值，并注明对应版本。
- 密钥、客户文档、内网地址一律不写入，示例用占位符。

## 编号与归档

- 编号分配后不复用，不因删除而回填。
- 被取代的专题移入 `docs/archive/kb/`，索引中保留一行去向说明。
- 合并时保留原始证据的 Git 提交或命令输出，不重新编造。

## 写入授权

新建或实质修改 KB 须用户明确要求。普通修复、排查和代码变更不自动获得回写授权。
