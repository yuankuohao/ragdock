# 部署与初始化

> 状态：现行。何时翻它：首次安装、迁移主机，或排查端口、磁盘、网络前提时。

## 前置

| 项 | 要求 |
|---|---|
| Docker | 24+，含 Compose v2（`docker compose version` 有输出即可） |
| 主机 | 4 核 8 GB 起；要跑本地 7B 模型则 16 GB 起 |
| 磁盘 | 50 GB（RAGFlow 镜像 + 向量库 + 原始文档） |
| 网络 | 首次部署需能拉镜像；隔离网走 `004_离线交付.md` |
| 端口 | 80（RAGFlow 网页）、9380（RAGFlow API）、4000（模型网关）、8088（企微适配） |

## 步骤

```bash
cp .env.example .env
vim .env          # 至少填 LLM_API_KEY、EMBED_API_KEY、LITELLM_MASTER_KEY
make fetch        # 下载 RAGFlow 官方 compose 到 upstream/
make up
make health
```

`make up` 做三件事：渲染网关配置 → 起 RAGFlow → 起网关与企微适配，最后轮询探活。

## 首次配置 RAGFlow（网页端，约 5 分钟）

1. 浏览器打开 `http://<主机IP>`，注册第一个账号（该账号即管理员）。
2. **模型供应商** → 新增 **OpenAI-API-Compatible**：
   - Base URL：`http://<主机IP>:4000/v1`
   - API Key：`.env` 里的 `LITELLM_MASTER_KEY`
   - 模型类型勾选 **Chat** 与 **Embedding**
3. **知识库** → 新建 → 选 Embedding 模型（列表里会出现 `embed-default` 和具体模型名）→ 上传文档 → 解析。
4. **聊天** → 新建助手 → 绑定知识库 → 复制助手 ID 填入 `.env` 的 `RAGFLOW_CHAT_ID`。
5. `docker compose up -d --force-recreate wecom` 让适配层读到新的助手 ID。
6. `make smoke` 验证三层链路。

> 解析扫描版 PDF 时，知识库的解析方法选 **General**，并把「版面识别」保持 `DeepDOC`，否则画质差的扫描件会丢失表格结构。

## 端口占用

RAGFlow 官方 compose 固定占用 80 与 9380。若主机已有 Nginx，改 `upstream/docker-compose.yml` 里的 `ports` 左侧值即可，同时把 `.env` 的 `RAGFLOW_BASE_URL` 指向新端口。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `wecom` 起不来，日志提示 `EncodingAESKey 解码后必须是 32 字节` | AES Key 少了字符或带了空格 | 从企微后台重新复制，长度应为 43 位 |
| 网关 502 / `Connection refused` | RAGFlow 还没起完 | `make health --wait`，RAGFlow 首次启动要 1–3 分钟 |
| 容器内连不上 RAGFlow | Linux 上 `host.docker.internal` 未映射 | 本 compose 已加 `extra_hosts: host-gateway`；自定义 compose 需自行添加 |
| 上传文档解析失败 | 扫描件无文字层 | 先用 OCR 转出文字版 PDF 再上传，或在 RAGFlow 里改用带 OCR 的解析管线 |
