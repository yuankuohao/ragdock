# 企业微信接入

> 状态：现行。何时翻它：创建企微自建应用、配置回调，或排查 403、解密失败、60020 时。

适配层做三件事：校验并解密回调、把问题转给 RAGFlow、把答案主动推回企微。

## 1. 企微后台配置

1. **应用管理 → 自建 → 创建应用**，记下 `AgentId` 和 `Secret`。
2. **我的企业** 页面底部复制 `企业 ID`（corp_id）。
3. 应用详情 → **接收消息 → 设置 API 接收**：
   - URL：`https://<你的域名>/wecom/callback`
   - Token：自己生成一串随机字符
   - EncodingAESKey：点「随机获取」，共 43 位
4. **企业可信 IP**：填这台服务器的**出口公网 IP**。不填则主动发消息报 `60020`。
5. 如需按部门路由到不同知识库，应用需有**通讯录读取**权限。

把以上五项填进 `.env`：

```ini
WECOM_CORP_ID=ww...
WECOM_AGENT_ID=1000002
WECOM_SECRET=...
WECOM_TOKEN=...
WECOM_AES_KEY=43位
WECOM_ROUTES={"2":"助手ID_A","3":"助手ID_B"}
```

`WECOM_ROUTES` 留 `{}` 表示所有人用 `RAGFLOW_CHAT_ID`。

## 2. 为什么要「先空响应再主动发」

企微要求回调 **5 秒内**返回，而一次 RAGFlow 检索 + 生成通常 5–20 秒。适配层的做法是立刻返回空 body（企微视为“无需回复”），随后在后台调 `message/send` 把答案推过去。

代价是**必须配置可信 IP**；收益是不会因为超时被企微重试三次、也不会出现重复回答。

## 3. 上线前自测

```bash
# 服务活着
curl -s localhost:8088/healthz | python3 -m json.tool

# 模拟一次验签（把 token/timestamp/nonce/echostr 换成真实值）
# 签名算法：sha1(sorted([token, timestamp, nonce, echostr]) 拼接)
```

`/healthz` 返回 `ok:true` 才说明五项企微参数与 RAGFlow 两项参数都齐了；`missing` 会列出缺哪几项。

## 4. 对话行为

| 项 | 行为 |
|---|---|
| 多轮记忆 | 按用户保留最近 `RAGFLOW_HISTORY_TURNS` 轮（默认 3），存在进程内存里 |
| 多副本 | 不支持共享记忆；要横向扩容先换 Redis |
| 非文本消息 | 直接忽略，不报错 |
| 超长答案 | 截断到 `WECOM_MAX_CHARS` 并加省略号 |
| 下游故障 | 回一句「服务暂时不可用」，异常写日志 |

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| 保存回调 URL 时报 `Invalid signature` | Token 与后台不一致；或 URL 带多余参数 |
| 能收到消息但没回复 | 看 `docker compose logs -f wecom`；多半是可信 IP 未配（`60020`）或 `RAGFLOW_CHAT_ID` 为空 |
| 回复「服务暂时不可用」 | RAGFlow 侧 401：`RAGFLOW_API_KEY` 与该助手不属于同一账号 |
| 部门路由不生效 | 应用无通讯录权限，日志会出现「读取部门失败」 |
| 内网部署收不到回调 | 企微回调必须公网可达；用反向代理或内网穿透，别直接暴露 8088 |
